Each row identifies a property, its actual state, a revision and the measurement behind it. A harness runs recorded
events or requests; a host measurement runs the real host. This table preserves the historical measurements cited in its
rows. A VERIFIED row applies only to the revision and environment named in that row; it is not a VERIFIED result for a
later gate. The earlier delivery used gate blob 1c4b7810 at edfb9ace. The Guard Preview stack reviewed on 2026-10-26 has
tree 229062a870ef002c8ad1fccba08100bc684abf69 and gate blob e3300f49. The harness results of that stack are those of the
supplied Guard Preview measurement package; they are not results for a later gate, whose harness results are those of
the tests at its own commit. The external D28 host runs remain historical observations, including row G-CX-3 and the
D28 cases of G-CC-5 that were not run again. Follow-up note 48 adds the owner answers O45-1 to O45-3 as decided and the
triage of PRODUCT_SPEC.md.

The release acceptance M1 for Claude Code ran at 6d29ead3 (gate blob a26c727e) on 2026-11-04: Claude Code 2.1.318 on
Linux, the plugins with their pin `proofbundle==6.4.0`, the model claude-opus-5-5 for every run with a real model. Each
case ran once, and two gate cases ran a second time with PROOFBUNDLE_OWNER_STATE=protected. A row that names 6d29ead3
refers to runs at that commit and names what did not run there, a second commit, another package version or a run
without a model. The harness run at 6d29ead3 took 355 test files of the plugin, the Guard, Codex, Claude Code, the done
check, the pilot and the gate with Python 3.10.12 and the package from the source tree: 13348 passed, 0 failed, 106
skipped (83 of them need Python 3.11). At this measurement V-CC-7 (TV-8) is FAILED, G-CC-13 (the pilot of TG-11) is NOT MEASURED, the record
of used releases on the operator's machine (G-CC-16) is not measurable with V6 at 6d29ead3, TG-6 was not
run in a host (G-CC-7), and the gate directory of TL-3 and TL-4 and a stale hook entry of TL-4 were not
checked (L-2, L-3). G-CC-3 (TG-1) has 14 different answers against the comparison head, all additional D129
blocks with none lost. The owner accepted these differences as an intended policy change on 2026-11-05; the
unchanged TG-1 requirement of zero different answers is still not met. The delivery-profile TG-9 run showed
a push proceeding without Guard protection, but did not emit the literal INACTIVE status required by
TEST_PLAN.md. At least acceptance points 1, 2, 4 and 8 remain unmet; Claude Code has not reached M1 at this
measurement. Each FAILED row is triaged by the four questions of PRODUCT_SPEC.md before it is called a
block of Verify, of the Guard, or of both. Codex was not measured in a host.
