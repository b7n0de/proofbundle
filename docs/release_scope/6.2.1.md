# Release scope — 6.2.1 (PATCH)

Written before the release, per the release gate in [RELEASE.md](../../RELEASE.md). It says what is in, what is
explicitly out, and why.

6.2.1 contains fifteen fixes, documentation updates and release-tooling changes. The third column describes
how each fix changes accepted input, evaluation or output.

## In

| Identifier | What is safer now | Effect on existing behaviour | Carried by |
|---|---|---|---|
| F1 | Repeated field names are rejected in review policies (`agent_review.load_policy`). | Refuses a policy file that 6.2.0 read with the last value of a repeated key; no new interface. | B1 |
| F2 | Replies from Chia with repeated field names are rejected (`anchors_chia_add`). | Refuses a node answer that 6.2.0 read with the last value of a repeated key; no new interface. | B1 |
| F3 | Credential checks reject unsupported requirements (`sdjwt_vc.check_vc_profile`). | Refuses an issuer header with an unsupported or malformed `crit` field that 6.2.0 accepted; no new interface. | B2 |
| F4 | A policy is checked at the same time as the receipt, including fractions of a second (`verify_decision_receipt`). | Judges the policy at the receipt's instant with its fraction of a second; within that second a verdict can change in either direction, which is the fix. | B3 |
| F5 | These verification commands require whole seconds (`decision verify`, `verify-enclave`). | Refuses a time whose fractional seconds are not all zero; a time with only zeros is taken as before. | B3 |
| F6 | These commands label results at a supplied time as HISTORICAL (`decision verify`, `verify-enclave`). | Adds the HISTORICAL label to the results of these two commands where it was missing. | B3 |
| F7 | One clock reading judges both ends of a policy's validity (the policy lifecycle evaluation). | Judges both ends of the validity window at one reading; at the edge of a window a verdict can change in either direction, which is the fix. | B3 |
| F8 | Policy time checks do not silently replace a supplied time with the current time (`policy_expired`, `policy_not_yet_valid`, `evaluate_policy`). | A malformed non-`None` `now` is no longer replaced by the wall clock; `None` keeps the default clock, and a naive datetime is read as UTC. | B3 |
| F9 | An enclave check rejects an invalid supplied time (`verify_enclave_attestation`). | Refuses a supplied `now` other than `None` unless its type is exactly `int`; `None` is unchanged. | B3 |
| F10 | Fractions of a second count when checking a claim's age (`check_freshness`). | Compares parsed timestamps without truncating the age to whole seconds; with `max_age_seconds` set, a negative age or an age above the bound is not fresh. The reported `age_seconds` rounds down, including when no bound is given. | B3 |
| F11 | The time is checked before it reaches the proof verifier (`verify_anchor`, `verify_anchors`). | Refuses a supplied `now` other than `None` unless its type is exactly `int`, before an anchor verifier runs; `None` is unchanged. | B3 |
| F12 | A log entry must match the proof that was checked (`evaluate_policy`). | Treats a checkpoint, the tree context and the root as authenticated only for the inclusion context `verify_bundle` verified. The result gains a `verified_inclusion_context` field after its existing fields. | B4 |
| F13 | An old key cannot approve its replacement using an unsupported signing method (`verify_trust_pack`). | An explicit unsupported or invalid `alg` on an old-root pin no longer counts as Ed25519; an absent `alg` and the bare-key form still mean Ed25519. | B5 |
| F14 | When two signature methods are required, one alone is not enough (`pack_key_binds_signer`). | Binds an Ed25519 outcome signature only to an Ed25519 pack key; no new interface. | B5 |
| F15 | An empty list of permitted log keys or sources grants no permission (`evaluate_public_transparency`). | An empty present list accepts no key or origin in its check; the key list applies when `requireSignedCheckpoint` is enabled. | B5 |
