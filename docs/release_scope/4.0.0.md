# Release scope — 4.0.0

## In
- **Origin-quorum rule** (`checkpoint.witness_quorum`, and with it `verify_witnessed_checkpoint`,
  `tlogproof.verify_tlog_proof`, `public_transparency`): a log does not vote in its own witness quorum
  — a cosignature is excluded when its key material equals the log's signing key OR its name equals the
  origin line, fail-closed before any signature math. Reason: closes self-cosignature quorum forgery,
  measured live 2026-08-16 (`witness_quorum(threshold=1) -> True` for a self-cosigned mini-log), decided
  in issue #7. **`witness_quorum`'s `log_key_material` is now REQUIRED** (was `= None`): pre-tag deep-gate
  D1 refuted the bare call — it silently ran name-only, so a log under an alias with its own key counted.
  Breaking for a direct caller of the primitive; the 3 shipped surfaces already pass it.
- **Printable-ASCII identity rule** for the origin AND witness name AND all three identity slots
  (`key_id`, `cosign_key_id`, `cosign_key_id_mldsa`, `sign_checkpoint`, `_parse_vkey`). Reason: a
  POSITIVE, non-enumerated rule closes the whole invisible/look-alike cloaking class at once (zero-width,
  NBSP, full-width, decomposed Unicode, the log-key-name slot), fail-closed. **BREAKING**: refuses a
  non-ASCII (IDN/Unicode) origin or witness name for the exact identity compare.
- **`public_transparency` fails closed on an unusable `log_vkey`** (F-9). Reason: a supplied-but-malformed
  `log_vkey` no longer silently switches off the key-material exclusion (a THIRD "not measurable" state).
- **`verify-proof` carries the exclusion reason on BOTH output paths** (F-6). Reason: the reader most
  likely to act saw nothing on the text path.
- **`_log_key_material_of` never raises** (F-7). Reason: a lone-surrogate log-vkey name can no longer
  escape as a raw traceback out of the public fail-closed surface.
- **The whole note body is validated UTF-8-safe before encoding** (pre-tag deep-gate D2/D3, class fix).
  Reason: a lone surrogate in the origin OR a C2SP extension line reached `.encode("utf-8")` before
  validation, raising a raw `UnicodeEncodeError` out of the public `verify_cosignature` /
  `evaluate_public_transparency` / `cosign_checkpoint` surfaces. Both note-body parsers (`verify_checkpoint`
  and the shared `_note_text_of`) now validate the full body first — the shared-parser neighbour was found
  by an independent pre-merge fix-review, not the first cut.
- **Corpus: 8-of-11 fixture coverage + a self-signed origin-quorum test vector**
  (`markovian_log/checkpoint_7397/`, `tests/test_origin_quorum_rule.py`). Reason: independent
  witness-key verification + the self-cosigned regression probe.
- **A killing test for the NFC-origin mutation operator** (this release's pre-tag closure, commit
  `6a1bdbe`). Reason: the pure-ASCII fixture origin could not reach the NFC case; a K-origin + KELVIN
  near-hit closes it, verified against the planted operator line.

## Out (explicitly deferred, no semantic change withheld from a caller who needs it)
- L2-01 (statuslist float-bits fail-closed) + L2-03 (intoto contentRootAlg present-but-malformed):
  local-only work, deferred to a post-4.0.0 release.
- `expected_origin` ASCII-validation inconsistency (un-review follow-up
  `PB-EXPECTED-ORIGIN-ASCII-INKONSISTENZ-01`): a maintainability class, NOT a hole in the shipped exact
  compare (the relying party pins its own `expected_origin`); post-4.0.0.

## Why MAJOR (the SemVer question, answered)
The printable-ASCII identity rule changes behaviour at a PUBLIC interface: a checkpoint whose origin or
witness name is non-ASCII (IDN/Unicode) — previously accepted — is now refused for the verifier's exact
identity compare. That is a new obligation on callers and a changed verdict at the boundary → SemVer
MAJOR, not a patch. Every shipped external vector (Go sumdb, Rekor, rootcommit, Colin's fixtures) is
pure ASCII and keeps its verdict; the break is for non-ASCII identities only, which no real tlog uses.

## Nachtrag (added 2026-08-18, after the release)

**This list did not name everything that shipped, and that is recorded here rather than quietly
corrected.** The finding is the same class the list itself is meant to prevent: a scope list that
does not contain what actually ships is the thing it was built against.

Measured after the fact: the last commit that touched this file is `dbf1a38`. Between it and the tag
`v4.0.0`, **two commits changed `src/`**:

| Commit | Files | Covered above? |
|---|---|---|
| `3b8ceb0` — *D2/D3 CLASS iter4: validate note-body size+root fields in `_note_text_of`* | `checkpoint.py` (+16/−0) | **thematically yes**, by the "whole note body is validated UTF-8-safe" entry — but that entry describes UTF-8 validation only, while the commit also adds uint64 size and base64 root validation to the shared parser. The entry understates its own scope. |
| `b47a806` — *iter5: type-guard every public producer argument (never-raise caller-contract)* | `checkpoint.py` (+15/−4), `tlogproof.py` (+13/−1) | **no, genuinely unnamed** |

`b47a806` is not cosmetic: it changes behaviour at public surfaces, turning a raw `TypeError` /
`AttributeError` on a wrong-typed producer argument into a typed `BundleFormatError`. Under the
project's own compatibility rules that is a tightening of previously accepted input and belongs in a
scope list and a changelog entry, not only in a commit message. It shipped in 4.0.0, which is a MAJOR
release, so it broke no promise that the release did not already break — but it was not declared.

**Why this is a note and not a guard.** `git grep release_scope` over all tracked files returns
prose only: no script, no test, no workflow reads these lists. The first checkbox of the release gate
has zero executable enforcement, so nothing would have caught this and nothing will catch the next
one. Building that guard is a separate, deliberate piece of work; pretending the gap is closed by
writing about it would be the same error one level up.

**Honest limit of this Nachtrag:** it records what was measured on 2026-08-18 against the tag. It
does not re-derive the full 3.7.1 finding (`PB-SCHNITTLISTE-ENTHAELT-NICHT-WAS-AUSGELIEFERT-WIRD-01`,
eight source files unnamed), which remains open and is about a different release.
