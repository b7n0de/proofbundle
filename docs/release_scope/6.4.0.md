### FOLGEPUNKT CL1, after 6.4.0: the container class of the core layer gate

| Item | What it is | State |
|---|---|---|
| CL1 | The core layer gate does not follow a value taken out of a container written out in the source | Open, register row after 6.4.0, by the owner word of 2026-10-23; not a named limit, not built in 6.4.0 |

The three forms, each in a core module that has bound the real `os` as `real`, measured on 2026-10-22 with the gate
of `main` 07b6122c and of the head `66b4e4c9` of pull request 395: the core reads the environment, and the gate says
GREEN with exit 0.

1. A subscript of a dict written out: `x = {"k": real}["k"]`, then `x.getenv("X")`.
2. A subscript of a list or a tuple written out: `x = [real][0]`, then `x.getenv("X")`; written inline,
   `[real][0].getenv("X")` is the same form.
3. Unpacking of a tuple written out: `x, y = real, 1`, then `x.getenv("X")`.

The control `x = real`, then `x.getenv("X")`, is RED with exit 1, as it should be.

The reason. The gate resolves a name through plain assignments, imports, star imports, re-exports and, with pull
request 395, the captures of a match statement whose subject it can read. A value placed into a container and taken
out again by a subscript or by unpacking is not resolved, so the name stands for a value the gate does not follow,
and an operation on it that the core may not perform is not seen. This breaks the property that every forbidden
operation in the core changes the verdict. It is the class of the P1 of the second Codex round on pull request 395,
one level wider than the match capture that pull request fixes, and it stands on `main` 07b6122c. The gate is
advisory in CI.

The test that would measure it. A parametrized case in `tests/test_core_layer_gate_sees_every_spelling.py`, in the
style of its cases for bindings made elsewhere: for each of the three forms, the core module is first run in a child
process with a test value for `X` to show that it reads the environment, and the gate is then asked for its verdict
on the synthetic package. The case is red while the gate says GREEN and green when the gate says RED with an
`environment` finding `os.getenv` in the core module. A control for each form puts a local class with a harmless
`getenv` into the container at the place the form takes out, and holds the gate GREEN, so that the fix follows the
value at its place instead of every value the container holds.
