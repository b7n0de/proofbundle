# Release scope — 6.4.0 (MINOR, draft)

Written before the release, per the release gate in [RELEASE.md](../../RELEASE.md). It says what is in, what is
explicitly out, and why. This file is a draft of 2026-10-21; each line below waits for the owner's word on it.

6.4.0 follows 6.3.1 directly; there is no 6.3.2 (owner decision of 2026-10-21). Its core is the SCITT anchor: a reader,
a producer and a Rust verifier for receipts in the CCF profile.

## Acceptance

Owner decision of 2026-10-21: 6.4.0 is accepted offline against two sets of material, and against nothing it does not
have.

- Real receipts of a foreign production ledger in the CCF profile, the Microsoft Signing Transparency ledger, collected
  on 2026-09-25 (work package AP7a).
- The lab chain of 2026-10-11.

The acceptance checks, each a separate result: an allowed profile, complete inputs, an admitted issuer, a valid
statement signature, a matching receipt binding, a matching data-hash binding, a correctly computed inclusion root and
a valid receipt signature under service trust that is configured independently. A missing precondition does not meet
the requirement, with `allow_pending` neither; the result is `ok=false` and `warn=false`. No trusted time is taken from
`anchoredAt`. The installed package is tested with and without the `scitt` extra.

Neither set of material is in this tree today. Where it lives in the tree is decided when the acceptance test lands.

Not a condition of 6.4.0: an own receipt with a Transparent Statement of a confirmed foreign operator (work package
AP7b). It is the target of a later release. The release texts of 6.4.0 say exactly what is proven and claim no own
registration with a foreign operator.
