### The release path

- Record the base commit and exact pull-request heads selected for the batch. Pull request 306 precedes 307, which lands as pull request 340. After 306 lands, check the remaining diff of 307 against the actual target branch and obtain the checks for that resulting state. Changed heads require a new check of their inclusion in the batch.
- If the up-to-date requirement is temporarily suspended, keep the other merge protections in force and limit the exception to the recorded batch. Restore and verify the original protection setting when the batch ends, including after an abort. Individual pull-request results do not certify the combined tree.
- After the batch and all release preparation, freeze the resulting main commit as candidate C. Run the complete release CI matrix, including the required Rust verifier, and the mutation layer on C. Record the commit and run identifiers and confirm that the required jobs actually completed successfully. Earlier heads, skipped jobs and cancelled runs are not evidence for these candidate checks. Trigger the mutation layer explicitly if the merge does not trigger it.
- Complete the chosen 24-hour soak on C. A change to the candidate starts a new candidate and invalidates evidence tied to the previous one. Collect the pre-tag receipt and the owner's signature for the checked candidate and its evidence before tagging.
- The tag must identify C. Repeat the defined post-tag measurements and record the exact distribution files and their digests. Before publication, confirm that these are the artifacts covered by the release checks and that the required post-tag checks have passed. If the tag workflow publishes before those checks, its ordering must be corrected. State the checks actually performed; this does not claim the full distribution-suite coverage recorded separately under N3-5.
