## In

### Headline change — `agent-review/v0.2` is what the emitter produces (the MAJOR-carrying change)
- `build_agent_review_statement` and `emit_agent_review` produce `agent-review/v0.2` without an
  argument; v0.1 needs an explicit `legacy_v01=True`, `v02=` is deprecated and warns (#185).
- v0.2 requires `subjectContext.disclosureCoreDigest` and `limitationCodes`, separates time claims
  by source, and accepts only the full 40-character `fixCommit` (`FIXCOMMIT_NOT_FULL_SHA`).
- A named policy axis: `policy_decision` in {`accept`, `insufficient_evidence`, `reject`} or `null`
  with `POLICY_NOT_EVALUATED` when no policy was given; the standard policy ships inside the package
  (`proofbundle/policies/agent-review-default-v1.json`, corpus copy byte-identical, kept so by a test).
- A time conflict on the event or observation axis is fatal (`TIME_CLAIMS_CONFLICT`,
  `time_consistency_ok`); a policy file may carry a `time` block, reported as `time_policy_decision`.
- A policy file is validated before it decides (`POLICY_NOT_EVALUABLE` on a malformed one).
- One dispatcher, `verify_agent_review_any`, for both versions: unknown keywords are a `TypeError`
  before the envelope is read, version-foreign keywords are dropped and named
  (`ARGUMENT_NOT_APPLICABLE_TO_VERSION`); the payload is decoded like `dsse.verify_envelope`.
- `POLICY_NOT_EVALUATED` and `AGENT_REVIEW_LEGACY_V01` live in `advisory_codes`; `reason_codes`
  stays fatal-only.
- The disclosure renderers take `legacy_v01=` and otherwise select v0.2 from three markers.
- `receipts/agent_review/` ships in the sdist; the six published v0.1 receipts run as a regression
  against values frozen under 5.1.0; the v0.1 verifier is byte-pinned to the 5.1.0 source.
- The `Receipt:` line of a published block is documented as the file hash, distinct from
  `receipt_digest()`.

Touches `src/proofbundle/agent_review.py` (+582) and `src/proofbundle/__init__.py`.

## Why MAJOR (the SemVer question, answered)
1. **A public emitter changes its default output.** A caller of `build_agent_review_statement` or
   `emit_agent_review` that passes no version argument received `agent-review/v0.1` under 5.1.0 and
   receives `agent-review/v0.2` under 6.0.0 — a predicate with required fields v0.1 never had, that
   a v0.1 verifier refuses. That is a changed contract at a public interface (Owner decision
   2026-09-02, "Thema 5, agent-review v0.2 freigeben").
2. **Two reason codes moved between result fields** (`reason_codes` → `advisory_codes`); no
   published release carried them, so no published consumer changes meaning — recorded, not a
   trigger on its own.

No verdict flips for published receipts: the six published v0.1 receipts verify as before (frozen
regression), `agent-review/v0.1` stays readable without a time limit, and v0.2 verification of a
valid predicate is unchanged unless it carries a time conflict, which was a false accept before.
